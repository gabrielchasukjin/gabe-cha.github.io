Improving LLM-Generated Educational Content: A Case Study on Prototyping, Prompt Engineering, and Evaluating a Tool for Generating Programming Problems for Data Science

SIGCSE TS 2026  ·  Feb 18–21, 2026  ·  St. Louis, MO · DOI
Jiaen Yu*, Ylesia Wu*, Gabriel Cha, Ayush Shah, Sam Lau  ·  University of California, San Diego
*co-first authors
PDF ACM Digital Library BibTeX

ContentGen is an open-source JupyterLab extension that generates programming practice questions inside the instructor's own notebook. The paper is an experience report on prototyping the tool, iteratively improving it through evidence-based prompt engineering, and evaluating the generated content against three pedagogical metrics.

The problem

Instructors of programming courses constantly need fresh practice questions. LLMs can plausibly write them, but output quality is inconsistent: questions can have subtle errors, hallucinations, or be pedagogically weak. That inconsistency is the bottleneck — it forces instructors to verify and edit every generation, which often costs more than authoring from scratch.

The tool

ContentGen lives inside JupyterLab as a sidebar extension. The workflow is:

  1. The instructor selects an existing notebook cell as the "inspiration" for a practice question.
  2. They optionally type a short prompt clarifying what they want.
  3. ContentGen generates a question and reference answer, displays them in the sidebar, and inserts a new cell below the source.
  4. The instructor can apply the suggestion, cancel it, or follow up with refinements.

The whole interaction stays inside the tool they already use to build course materials — no separate web app, no copy-pasting between contexts.

Three design goals

  • D1 — In-workflow: live where the instructor already works (JupyterLab).
  • D2 — Automatic context discovery: the tool should figure out what context to send the LLM, not force the instructor to assemble it.
  • D3 — Effective for instruction: generated questions should be correct (solution code runs), have contextual fit (use the lecture's datasets and idioms), and be coherent (actually assess the right topic).

Evaluation

We open-sourced a dataset of 91 test cases drawn from real course materials at UC San Diego and used three binary metrics tracking D3: Correctness, Contextual Fit, and Coherence.

Three prompting strategies were compared:

  • Baseline — generic instructions plus the entire notebook as context.
  • Detailed — step-by-step instructions with variable information.
  • Structured — detailed instructions plus an automatically generated summary of the lecture content, organized by pedagogical topic.

The Structured prompt substantially improved generated-question quality across all three metrics relative to the Baseline. A usability study with six data science instructors further showed the final prototype was perceived as useful and effective.

My role

I contributed to system implementation and evaluation as a co-author alongside Jiaen Yu and Ylesia Wu (co-first authors), Ayush Shah, and Sam Lau.
